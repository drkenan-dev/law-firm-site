# Crestline Law Partners — Law Firm Website

A modern, fully responsive law firm website built with **Next.js (App Router)**, **TypeScript**, and **Tailwind CSS v4**. Content is editable two ways: dummy placeholder data in `src/data/`, or — once connected — a **WordPress CMS** that rebuilds the site and auto-deploys to Bluehost on every publish (see [`CMS-SETUP.md`](CMS-SETUP.md)).

---

## Stack

- **Next.js 16** (App Router, static export)
- **TypeScript** (strict)
- **Tailwind CSS v4** (CSS-first configuration in `src/app/globals.css`)
- **lucide-react** (icons)
- Fonts: **Playfair Display** (serif headings) + **Inter** (body) via `next/font`
- **Optional CMS:** WordPress + Advanced Custom Fields (plugin in `cms/wordpress/crl-headless`), deployed via GitHub Actions → FTP → Bluehost

---

## Getting started

```bash
npm install          # install dependencies
npm run dev          # start the dev server → http://localhost:3000
```

> `npm run dev`/`npm run build` always regenerate `src/lib/content.generated.ts` first
> (`predev`/`prebuild` hooks). With `WP_API_URL` set in `.env.local`, content comes
> from WordPress; otherwise the seed data in `src/data/` is used.

Other commands:

```bash
npm run build           # production build (also type-checks) → exports to out/
npm run start           # serve a production build locally
npm run lint            # ESLint
npm run sync:content    # re-pull content from WordPress into src/lib/content.generated.ts
npm run generate:images # regenerate the placeholder SVG images
```

## ✏️ Editing content

Two ways, same data model:

1. **WordPress (recommended, no code)** — follow [`CMS-SETUP.md`](CMS-SETUP.md). Publish
   content in WordPress and the site rebuilds and deploys automatically.
   The build pulls `…/wp-json/crl/v1/all` from the plugin's REST endpoint via
   `scripts/sync-content.ts`.
2. **Code (offline/dev)** — edit the seed files in `src/data/` below. They double as
   the fallback whenever a WordPress collection is empty or unreachable.

### Seed files

| File | What it controls |
| --- | --- |
| `src/data/firm.ts` | Firm name, tagline, address, phone, email, hours, socials, statistics + static nav/why-choose-us/timeline/values |
| `src/data/attorneys.ts` | Attorney names, bios, photos, positions, education, practice areas, etc. |
| `src/data/practiceAreas.ts` | All 10 practice areas (card text + full detail-page content) |
| `src/data/testimonials.ts` | Client testimonials |
| `src/data/cases.ts` | Case results / success stories |
| `src/data/blog.ts` | Blog articles (listings + full article content) |
| `src/data/faqs.ts` | FAQ questions (grouped + filterable) |
| `src/data/careers.ts` | Vacancies, benefits, culture, internships |

**Rules that keep it easy:**
- Attorneys use `slug` + `photo` keys — keep filenames matching the `photo` path.
- Blog posts reference `authorSlug` that must match an attorney `slug`.
- Case results reference `practiceAreaSlug` that must match a practice area `slug`.
- Practice area `image`, attorney `photo`, blog `image` all reference files in `public/images/`.
- Every page/component reads editable collections through `@/lib/content`
  (not `@/data/*`) so data has one single source at runtime.

### Changing the brand

1. `src/data/firm.ts` → `name`, `tagline`, `description`, contact details.
2. `src/app/globals.css` → `@theme` block for navy/gold colors and fonts.
3. `src/lib/site.ts` → `siteConfig` URL + default SEO copy.

## 🖼️ Swapping images

Images live in `public/images/`, organized by use:

```
public/images/
  hero/            hero-home.svg, hero-interior.svg
  general/         og-cover.svg (social preview), about-office.svg, careers.svg, commitment.svg
  attorneys/       attorney-1.svg … attorney-6.svg
  practice-areas/  one per practice area
  blog/            blog-*.svg
```

**To replace a photo:** drop your file into the matching folder with the **same filename** (e.g. replace `public/images/attorneys/attorney-1.svg` with `attorney-1.jpg` if you prefer JPG). No code changes needed — the paths are resolved from the data files. Recommended minimums: portraits 600×720+, covers/heroes 1200×800+, og-cover 1200×630.

The current placeholders are generated by `scripts/generate-placeholders.mjs` (run `npm run generate:images`). They are intentionally on-brand, abstract illustrations — safe to overwrite for real photography.

## 🌐 Environment variables

| Variable | Purpose | Default |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Canonical URL used in metadata, sitemap & robots | `https://examplelawfirm.com` |
| `WP_API_URL` | WordPress base URL the build pulls content from | *(unset → seed data)* |

Create a `.env.local` file (see `.env.example`):

```
NEXT_PUBLIC_SITE_URL=https://www.your-firm-domain.com
WP_API_URL=https://www.your-firm-domain.com/wp
```

`NEXT_PUBLIC_SITE_URL` and `WP_API_URL` are also the GitHub Actions secrets used in
the deploy workflow (`WP_API_URL` is set as a build-time secret there).

## 🚀 Deployment (Bluehost)

The site builds to a fully static export (`out/`) — no server runtime needed.

- **GitHub Actions** (`.github/workflows/deploy.yml`) runs on every push to `main`,
  on manual trigger, and on a WordPress `wp-publish` event. It runs
  `npm run build` (pulling content from `WP_API_URL`) then FTP-uploads `out/`
  to Bluehost via `SamKirkland/FTP-Deploy-Action@v4`.
- Required repo secrets: `WP_API_URL`, `FTP_SERVER`, `FTP_USERNAME`,
  `FTP_PASSWORD`, `FTP_DIR`.
- The WordPress plugin triggers the workflow automatically when content is
  published (Settings → Crestline Headless). Full walkthrough: **[`CMS-SETUP.md`](CMS-SETUP.md)**.

## 🖥️ Future backend integrations

The site is frontend-only by design. Forms validate locally and show a confirmation state, but nothing is transmitted. To go live:

1. **Contact / consultation / career forms** — add API routes (`app/api/contact/route.ts`, `app/api/consultations/route.ts`, `app/api/careers/route.ts`) and POST the submitted values from `src/components/forms/*` (each form already has a clearly-marked comment at the `setTimeout` where the `fetch` call goes).
2. **Email delivery** — connect a service such as **Resend**, **SendGrid** or **Mailgun** from those routes (SMTP or API; store keys in `.env.local`).
3. **Newsletter** — `src/components/layout/NewsletterForm.tsx` → POST to `/api/newsletter` writing to a service like Mailchimp.
4. **Consultation scheduling** — optional calendar integration (e.g. Calendly) replacing or complementing the favourite-date/time form.
5. **Remote images** — if you serve images from a CDN, add `remotePatterns` in `next.config.ts` (example included) and remove the `unoptimized` prop from the `<Image>` usages.

> **Legal note:** before publishing, have the privacy policy and terms reviewed by a lawyer, and replace any illustrative "case results" with real (permitted) matters.

## Accessibility & performance notes

- Semantic HTML, skip-to-content link, visible focus rings, `aria` states on menus/accordions/forms.
- All images lazy-loaded (`next/image`) with descriptive alt text.
- Scroll-reveal animations respect `prefers-reduced-motion` and are disabled under it.
- Fully responsive from 320px to 1920px with no horizontal scrolling; tested grid, navigation, forms and images.
